# 桌面响应性能与 Rust 分阶段迁移

更新：2026-11-15。目标分支：`upstream-update`。

## 第一阶段：退出卡顿修复

当前前端由 Wails 调用系统 WebView 渲染；Windows 使用 WebView2，后端为 Go。
本阶段仍使用现有后端，没有引入 Rust 或替换代理连接栈。

本次修改：

- WebView2 使用默认 GPU 加速；旧驱动确有兼容问题时，可通过进程环境变量 `LIANXIANG_WEBVIEW_DISABLE_GPU=1` 恢复软件渲染。
- 弹窗移除全屏模糊、动态渐变和扫光，只动画透明度与位移；进入 160ms、退出 140ms，取消 680ms 遮罩停留。
- 关闭回调的磁盘日志移至后台，避免同步刷盘阻塞窗口线程。
- 退出请求立即返回，完整清理在后台执行，界面显示正在关闭；去掉前端固定延迟和 1.2 秒后再次退出的竞争调用。
- 第一次退出请求确定退出模式，重复点击不会改变“仅退出应用”或“退出应用与浏览器”的选择；后台任务仅等待一次。

验证：前端构建、Windows 生产编译；退出状态和异步清理回归测试；隔离数据目录下实际打开、取消、再次打开关闭弹窗，以及仅退出应用。
桌面验证时没有启动浏览器实例，因此保留运行实例和大量实例同时退出仍需在对应场景验证；没有测量帧率，不据此承诺固定响应时间。

## 第二阶段：桌面接口兼容层

已完成前端命令调用、事件订阅和窗口操作的统一入口 `frontend/src/desktop`。
业务页面不再直接导入 Wails 绑定或读取 Wails 全局对象；默认宿主仍是 Wails + Go，Rust 后端尚未接入。

- 复用生成的 Go 接口类型与调用包装，保留 213 个命令名称、位置参数、返回对象、未知字段和原始错误；不增加序列化或持久化步骤。
- 后续宿主通过 `DesktopHost` 契约接入，只允许在界面启动前选择，防止运行中的操作被切换到另一个后端。
- 事件监听返回独立取消函数，页面卸载不再按事件名清除其他页面的监听；兼容异步注册时页面已卸载的情况。
- 操作日志改为观察统一调用入口，不修改宿主的全局方法；日志失败不影响实际操作结果。
- 本阶段没有修改任何后端数据读写、SQLite 表结构、配置文件格式、实例路径或代理连接栈，也没有搬迁、升级或清理实际用户数据。

验证记录：

- `cd frontend; npm.cmd run test:desktop`：10 项测试通过，覆盖全部 213 个生成命令的参数/返回值透传、错误、替代宿主、事件清理、窗口操作、日志与接口边界。此测试使用 Node 的 TypeScript 类型擦除功能，需要 Node 22.18+ 或 24+。
- `npm.cmd run build:keep`：TypeScript 检查和生产前端打包通过。
- `go test ./backend ./backend/internal/browser -run 'Test.*(Bookmark|ChromeUserData|ImportChrome|FullQuit|AppOnlyQuit)' -count=1`：书签、Chrome 导入与退出回归通过，使用测试临时目录。
- Windows 生产编译通过，输出 `build/bin/lianxiang-browser-desktop-adapter.exe`。
- 实际桌面验证在 `.local-tools/desktop-adapter-smoke` 独立目录进行，使用模板配置、独立数据库和 `use_custom_data_dir: false`；实例列表、书签读取、关闭弹窗、取消和仅退出应用通过。没有使用真实 Chrome 用户目录或启动浏览器实例。

## 后续迁移顺序（尚未实现）

1. 优先迁移只读的本地任务，如目录扫描、校验与导入预检。Rust 模块采用可取消任务，回传进度，通过临时数据夹具验证结果与当前实现一致。先不接管文件复制、导入落盘或数据库写入。
2. 再逐项迁移文件复制、实例进程管理、退出协调和持久化。先覆盖“仅退出应用时浏览器与代理仍可用”、重复退出、备份导入失败回滚及既有 SQLite 格式读写兼容，再切换默认实现；不执行用户数据格式迁移。
3. 业务接口迁移完成后切换 Tauri 桌面宿主，继续复用系统 WebView 和现有 React 页面。每阶段保留可回退的发布版本。

迁移约束：数据目录与数据库格式保持兼容；Xray + sing-box 组合栈和独立 Mihomo 栈保持明确边界，不因迁移增加自动跨栈回退。
Rust 不能替代对渲染、磁盘等待和线程阻塞的定位；每阶段均按同样负载比较响应和资源使用。
