# 桌面响应性能与 Rust 分阶段迁移

更新：2026-11-15。目标分支：`upstream-update`。

## 第一阶段：退出卡顿修复

当前前端由 Wails 调用系统 WebView 渲染；Windows 使用 WebView2，后端为 Go。
本阶段仍使用现有后端，没有引入 Rust 或替换代理连接栈。

本次修改：

- WebView2 使用默认 GPU 加速；旧驱动确有兼容问题时，可通过进程环境变量 `LIANXIANG_WEBVIEW_DISABLE_GPU=1` 恢复软件渲染。
- 弹窗移除全屏模糊、动态渐变和扫光，只动画透明度与位移；进入 160ms、退出 140ms，取消 680ms 遮罩停留。
- 关闭回调的磁盘日志移至后台，避免同步刷盘阻塞窗口线程。
- 退出请求立即返回，完整清理在后台执行，界面显示正在关闭；去掉前端固定延迟和 1.2 秒后再次退出的竞争调用。
- 第一次退出请求确定退出模式，重复点击不会改变“仅退出应用”或“退出应用与浏览器”的选择；后台任务仅等待一次。

验证：前端构建、Windows 生产编译；退出状态和异步清理回归测试；隔离数据目录下实际打开、取消、再次打开关闭弹窗，以及仅退出应用。
桌面验证时没有启动浏览器实例，因此保留运行实例和大量实例同时退出仍需在对应场景验证；没有测量帧率，不据此承诺固定响应时间。

## 后续迁移顺序（尚未实现）

1. 提取前端桌面接口：窗口操作、事件订阅、命令调用统一到适配层，保持现有 Go DTO、错误和事件语义。为 Tauri/Rust 实现同样的契约。
2. 优先迁移边界清楚的本地任务，如目录扫描、文件复制、校验与导入预检。Rust 模块采用可取消任务，回传进度，通过真实数据夹具验证结果与当前实现一致。
3. 再迁移实例进程管理、退出协调和持久化。先覆盖“仅退出应用时浏览器与代理仍可用”、重复退出、备份导入失败回滚、既有 SQLite 数据迁移，再切换默认实现。
4. 业务接口迁移完成后切换 Tauri 桌面宿主，继续复用系统 WebView 和现有 React 页面。每阶段保留可回退的发布版本。

迁移约束：数据目录与数据库格式保持兼容；Xray + sing-box 组合栈和独立 Mihomo 栈保持明确边界，不因迁移增加自动跨栈回退。
Rust 不能替代对渲染、磁盘等待和线程阻塞的定位；每阶段均按同样负载比较响应和资源使用。
